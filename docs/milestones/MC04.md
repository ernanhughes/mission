# MC04 — Windows launching and process management

## Delivered

- Native detached Windows process launches using `subprocess.Popen`
- Structured argument arrays, no shell
- Working-directory validation
- Port-conflict preflight for enabled expected ports
- Duplicate-launch and managed-process-limit guards
- Log redirection and on-read redaction
- Health probes (HTTP/TCP) for enabled definitions
- Ownership states: managed, external, none/unknown
- Stop only after PID + creation-time verification; recursive child termination via psutil
- Startup reconciliation and reattachment
- Configurable editor invocation for repositories and documentation files; native executable requirement
- Explicit process logs and failure diagnostics

## Important discovery and fix

`asyncio.create_subprocess_exec` transports kill the child when their event loop closes on Windows. This was observed during the restart test. Managed launches now use detached `Popen` children. This makes backend restart reattachment genuine rather than simulated.

## Limitation

A launcher executable that immediately exits while leaving a grandchild running cannot be reattached reliably. The user should configure the native long-lived executable. Mission Control marks an identity mismatch as lost and refuses to kill a guessed process.
