# W4-COMPLETION-SEMANTICS — Governed by mandatory requirements

`rollup_completion`: complete iff every mandatory requirement is
`satisfied_verified`. Reported-only is never complete; partial/unknown where
evidence is thin; incomplete on any unsatisfied/contradicted mandatory item;
blocked where flagged; unknown where mandatory items are unassessed.

Kind-specific acceptance (no commit required for legitimate non-code work;
no deployment required where deployment was excluded; authorized
implementation-only stages are not incomplete for pending later stages).
Stage/episode/programme/product completion are separate verdicts; parent
completion is never inferred from children. Research, investigation and
documentation episodes complete on artifact + review, not on code.

Pilot: no episode reached `complete` — correctly, since nothing in the pilot
was independently verified end-to-end. `incomplete` fired once (AI-CORE-05,
mandatory requirements unsatisfied); the rest are honestly `unknown`.
A system that cannot say "unknown" cannot be trusted to say "complete".
