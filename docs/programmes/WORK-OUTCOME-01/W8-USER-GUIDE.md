# W8-USER-GUIDE — Prospective work in plain language

**Where**: Activity → Work Evaluation (operational `:8790`; W8
screens validated on the scratch stack).

**Registering work before it starts** (new in W8): an envelope binds
the episode, objective, requirement versions, repositories,
authorization and acceptance policy into one digest-pinned record.
Create requirements first (human-reviewed, W6A path), then register —
unknown references are rejected, duplicates collapse, changes version.

**Running it**: execute wherever the commission says (manual copy,
worker, workbench, OpenCode). Record the handoff with session, commit,
test receipt and review pointers — the system traces, never runs.

**Afterwards**: re-evaluate; the assessment joins requirement versions
at the recorded digest. New evidence appends; staleness marks
re-evaluation; closure still needs cited evidence + a named human.

**What fits on one screen**: the envelope is ~700 bytes of metadata.
It never carries conversations or evidence packets into model context.

**What is manual today**: worker/workbench propagation (channels
designed, links recorded by hand); test receipts (link the id;
AITest holds the body); independent review (graded, never assumed).
The schedule stays off; paid inference stays $0 and unwirable.
