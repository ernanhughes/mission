# H1 Research to Capability Mapping

| Research lesson | Local capability / owner | H2 consequence |
|---|---|---|
| Protected mechanism and replaceable harness | Mission policy/action authority + Worker executor and Pi/OpenCode engine | Keep governance outside candidate-controlled runtime; explicit engine adapter boundary. |
| Durable run and auditable event history | Mission episodes/observations (WIP), Worker Work/VFS and observability | Establish one trace identity and link existing records; do not create a parallel ledger before examining durable contracts. |
| Candidate isolation and fixed evaluator | Praxis manifests/effectiveness; Mission workflow approval | Freeze candidate and evaluator digests; candidate cannot edit acceptance material. |
| Holdout and selection-bias control | Praxis experiment methods; AITest observe-mode pilot only | Separate development, validation, and protected acceptance data; report uncertainty. |
| Independent verifier | Worker declared checks/Proof, Mission outcome evidence, Praxis evaluation | Keep execution acceptance, domain correctness, and effectiveness as distinct decisions. |
| Cost and matched comparisons | Worker actual/estimated cost distinction; Praxis comparison reports | Match total budgets and report unknown cost as unknown. |
| Benchmark/evaluator integrity | Mission governance and evidence provenance | Protect task, evaluator, and result digests and record access/change history. |
| Process/content failure separation | Worker failure records + Praxis H05 | Attribute failure before proposing a change; abstain on insufficient evidence. |

The external material supports safeguards and vocabulary, not a local capability gap by itself.
